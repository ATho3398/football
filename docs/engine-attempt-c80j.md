# C.80j 53단계_직선 전환 받은 뒤 공격 — 시도 기록 (미해결, main 미반영)

마스터 AD 지시 `docs/session-prompts/C.80j.md`(claude/planning-ad). 브랜치 `claude/c80j-switch-followup`(origin/main 1f0c7ad C.80i 위). Opus.

## 결론
- **목표 미달 — main 푸시 안 함.** 반대 전환 받은 뒤 판단 보정(몰기·안쪽 몰기·드리블·크로스·컷백·짧은 전진·슛 가산, 앞 롱볼 감점)을 크게 넣어도 **받은 뒤 10초 xG/받음은 0.004~0.007**(목표 ≥ 0.010)에 머문다. 받은 선수의 다음 행동 비율은 크게 바뀌지만(몰기 22 → 49%, 짧은 전진 10 → 23%, 슛 1 → 6%, 10초 안 슈팅 9 → 19%) xG 는 그대로.
- **앞 롱볼 ≤ 10% 는 됨**: 앞 롱볼 감점 `switchFollowLong` 0.3(0.3 과 1.0 결과 같음 — 포화) + 조건 넓힘(x ≥ 0.3 · 측면 |y−0.5| ≥ 0.1 · 5 m 안 상대 ≤ 2) → 16.7 → **8.5%**. 하지만 xG 는 0.007 → 0.007.
- **같은 보정을 균형 팀에 주면 오히려 나빠짐**(균형 xG/받음 0.012 → 0.009, 득실 +0.24 → −0.01). → 받은 선수의 첫 1~2 터치 판단이 아니라, 전환을 받는 자리·박스 안 지원(구조) 쪽 차이로 보임. 이 문제(전환 뒤 공격 약함)는 C.80i 에 이어 **두 번째 미해결** → 자동 진행 멈춤 조건 ①.
- 코드(전부 꺼짐, 엔진 동작 불변 · test 164파일 1321 ✓ · typecheck ✓)는 이 브랜치에만 둔다: `config.ts decide.bias.switchFollow*`(Dribble·Carry·Cross·Fwd·Shoot·Long = 0, Direct 1, Dy 25, Wide 0.2, FromX 0.5, Free 5, MaxOpp 1, Time 8, Touch 1, LongFrom 20, LongFwd 10) · `actions.ts markSwitchFollow()`(받는 순간 팀 `swAt`·`swN` 기록) · `onball.ts candidates()` 항 · `state.ts`/`sim.ts` 팀 필드.

## 추천 다음 처방 (엔진관리자 재진단 대상)
1. 측정 단위 문제: 직선은 전환을 균형의 두 배(25 대 12/경기) 하므로 받음당 xG 가 묽어진다 — 경기당 전환 뒤 xG 합은 직선 25×0.67×0.007 ≈ 0.12 > 균형 12×0.61×0.012 ≈ 0.09. 목표를 받음당이 아니라 경기당 합·칸 득실로 다시 정할지.
2. 구조: 전환 받는 순간 박스 안·하프스페이스 동료 수(지원 침투) 측정 → 부족하면 오프볼(반대 측면 전환 때 박스 침투 수) 쪽. "수치 먼저" 원칙상 오프볼 침투 확률 계수 레버 후보.
3. 직선 전환 빈도 자체(`directSwitchScan` 0.3)를 낮춰 받음 질을 올리는 쪽은 C.80i 칸 이득(+0.071)과 맞바꿈.
