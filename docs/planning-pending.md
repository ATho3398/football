# 기획 대기 메모 (기획서 반영 대기)

11단계 코드 세션(C.22)이 도는 동안에는 `docs/game-design.md`를 고치지 않는다(인수인계 1번 규칙). 그동안 확정한 내용을 여기에 모아 두고, **C.22가 끝나면 기획서에 합친 뒤 이 파일을 지운다.**

## 1. D.17 결정 (2026-10-15, 사용자: 추천대로) → 부록 D.17로 옮긴다 — **기획서 합침 완료(D.17, E.19, 21.3·21.4)**
1. **12단계(E3.6 전술 화면) 시작 시점**: C.22가 배포된 뒤 사용자가 사이트를 직접 확인(5분)하고 나서 새 코드 세션을 연다. 코드 세션은 한 번에 하나만 돌린다.
2. **E3.6 전술 검증 규모**: 성향 6×6 매트릭스는 **칸마다 50경기로 먼저** 돌리고, 영향 상한(동레이팅 경기당 득실차 ±0.3골)을 넘는 칸만 100경기로 다시 잰다. 세부 전술 4개의 짝지은 비교(200경기)는 그대로 필수다. → E.19 "검증" 줄을 고친다.
3. **E3.6에서 전술 변경 시점**: 경기 전 설정과 "기본 전술 저장"(바꾸기 전까지 매 경기 유지)만 넣는다. 하프타임과 경기가 멈췄을 때 바꾸는 기능은 E5(경기 화면)로 미룬다. → E.19 "범위와 원칙" 첫 줄에 단계 표시를 붙인다.
4. **C.22를 기다리는 동안 기획 세션 작업**: 복잡도 관리(단계적 공개, 21.3)와 첫 플레이 안내(21.4)를 구체화한다. 결과는 21.3·21.4 개정으로 넣는다.

## 2. 엔진 다듬기에 추가: 골 후 킥오프 정지와 순간이동 (사용자 제보, 2026-10-15) → D.16 4번 목록과 엔진 다듬기 명세에 넣는다 — **기획서 합침 완료(D.18 1, 24.3, D.16 4번)**
**사용자 제보**: "실시간으로 엔진 돌리는 걸 보니 골 넣은 다음 움직임이 이상하다. 킥오프를 안 하고 몇십 초 동안 가만히 있다가, 갑자기 선수들이 순간이동한다."

**기획 세션 조사 (코드 읽기 + 진단 시뮬 20경기, 레이팅 80 대 72, C.21 엔진)**
| 증상 | 원인 | 측정 |
|---|---|---|
| 골 뒤 수십 초 정지 | 골 후 킥오프 대기가 설정값 `ENGINE.restart.kickoff` = **45~75초**(실제 세리머니·재정렬 시간을 흉내 낸 값)다. 선수들은 10~20초 안에 자기 진영으로 돌아온 뒤 남은 시간 동안 제자리에 서 있다. 세리머니 동작이 없고, 실시간 재생은 이 시간을 1×로 그대로 보여 준다 | 골 → 킥오프 평균 59초 |
| 순간이동 ① 골키퍼 | GK가 공을 잡거나 처리할 때 위치가 공 쪽으로 한 번에 옮겨진다 | 한 번에 **4~12 m**, 경기마다 여러 번 |
| 순간이동 ② 재개 키커 | `executeRestart`(sim.ts)가 키커를 공 위치로 바로 옮긴다. 대기 시간 + 4초 안에 키커가 공에 못 오면 그 거리만큼 순간이동한다(스로인이 가장 큼). 후반 킥오프는 하프타임 대형(`kickoffPositions`)이 중앙에서 약 4 m 떨어져 있어서 매번 4.2 m 순간이동한다 | 스로인 **10~36 m**, 후반 킥오프 4.2 m |
| 순간이동 ③ 공 받는 선수 | 경기 중 공을 받거나 뺏는 순간 소유자가 공 쪽으로 1.5~2 m 당겨진다(작아서 끊김 정도로 보인다) | 경기당 약 17회 |

**엔진 다듬기에서 할 일(초안, 결과 할당 금지 원칙 E.15.1 유지)**
1. **골 세리머니 동작**: 득점자 쪽으로 같은 팀 3~5명이 모였다가(약 15~20초) 자기 진영으로 걸어 돌아온다. 실점 팀은 바로 자리로 걸어간다. 킥오프 대기 시간(45~75초)은 시계와 통계에 영향이 있으므로 그대로 둔다.
2. **재생 쪽 공 죽은 시간 빨리감기**: 실시간 모드에서 재개 대기 중 모두가 자리를 잡은 뒤 남은 시간은 자동으로 빠르게 넘긴다(시계만 빠르게, 24.3 원칙과 같다). 재개 대기 라벨(21.5.2)을 같이 띄운다. 엔진·밸런스 영향 없음.
3. **순간이동 제거**: GK 처리, 재개 키커, 공 소유 시작 모두 "위치를 옮기기"가 아니라 "그 자리까지 달려가기(또는 공이 선수 발로 오기)"로 바꾼다. 재개 키커가 늦으면 재개를 조금 더 미룬다(최대 +10초). 하프타임 킥오프 대형에서 키커를 중앙 점에 둔다.
4. **검증**: 0.1초에 1.5 m(초속 15 m)를 넘게 움직이는 선수가 하프타임 순간을 빼고 **0회**여야 한다. 이 진단을 테스트나 `balance:engine:check`에 넣는다. 득점·선방·점유 지표가 C.21과 크게 달라지지 않아야 한다(공 잡는 위치가 바뀌면 GK 선방률이 움직일 수 있으니 같이 보고한다).

## 3. 엔진 다듬기에 추가: 골키퍼가 루즈볼을 받으러 나오지 않음 (사용자 제보, 2026-10-15) → 2번과 같은 곳에 넣는다 — **기획서 합침 완료(D.18 2, E.9)**
**사용자 제보**: "골키퍼가 눈앞까지 공이 와도 안 받으러 간다. 결국 상대가 공을 잡아 공격 기회를 받았다. 클래식 키퍼여도 볼을 돌리거나, 박스 주변에 아무도 없는데 자기 쪽으로 오면 받긴 해야 한다."

**기획 세션 조사 (코드 읽기 + 진단 시뮬 10경기, 레이팅 78 대 76, C.21 엔진)**
- **원인(코드)**: 오프더볼 목표(`offball.ts updateOffball`)에서 GK는 루즈볼 판단보다 먼저 `keeperTarget`으로 빠진다. `keeperTarget`은 골라인 앞 깊이와 좌우만 정하고, **상대가 공을 몰고 박스 안 골 가까이 왔을 때만** 각을 좁히러 나간다. 루즈볼 추격자 선정(`ballRank`, `chasers` 2명)도 GK를 뺀다. 그래서 **아무도 소유하지 않은 공에는 GK가 절대 움직이지 않는다.** 공 컨트롤 판정(`updateLooseBall`)은 GK도 받지만 거리 0.9 m 안에 공이 우연히 굴러와야 하고, 손 처리(핸들링)는 쓰지 않는다.
- 패스로 GK에게 보내는 백패스(볼 돌리기)는 받는 선수 경로로 처리돼서 정상이다. 문제는 **루즈볼**(빗나간 패스, 굴절, 너무 긴 스루패스, 약한 슛)이다.
- **측정**: 박스 안 루즈볼에서 GK가 다른 모든 선수보다 3 m 이상 가까웠던 경우가 10경기에 **177회**(클래식 107, 스위퍼 70). 그중 **GK가 잡은 횟수 0회**. 결과는 골라인 밖으로 굴러나가 우리 골킥 107, **상대 코너 26**, 상대가 공을 잡음 13, 우리 수비수가 잡음 17, 상대 스로인 8 등이다. 경기당 약 18회 GK가 멀뚱히 서 있고, 그중 약 4회는 상대에게 코너나 공을 내준다.

**엔진 다듬기에서 할 일(초안)**
1. **GK 루즈볼 처리**: 공이 자기 박스 안에 있거나 박스로 굴러 들어오고, GK의 도착 시간이 가장 빠른 상대보다 빠르면(여유 0.5초) GK가 공으로 달려나간다. **클래식·스위퍼 모두** 박스 안은 반드시 나간다. 박스 밖은 스위퍼만 나가고, 범위는 출전 범위(commandOfArea)와 가속에 비례(약 5~20 m)한다. 우리 수비수가 더 빠르면 수비수에게 맡긴다(둘이 같이 가지 않는다).
2. **박스 안 손 처리**: 박스 안에서 GK의 공 처리 거리는 1.5 m(손)로 넓히고 성공률은 핸들링으로 정한다. 같은 팀이 발로 일부러 준 백패스는 손을 쓰지 못하고 발 컨트롤(현행)로 받는다.
3. **스루패스 끊기**: 상대 스루패스가 박스 근처 뒷공간으로 갈 때 GK 도착이 공격수보다 빠르면 나와서 끊는다(스위퍼는 박스 밖까지). 패스 판단 쪽에서 상대 GK의 도착 시간을 가로채기 후보로 넣는다.
4. **검증**: 위 진단(박스 안 루즈볼에서 GK가 3 m 이상 가장 가까운 경우)에서 **GK 처리율 70% 이상**, 상대 코너로 끝나는 비율 5% 이하. 선방률, 실점, 클린시트, 스위퍼 대 클래식 차이(스위퍼가 뒷공간 처리를 더 많이 해야 한다)를 같이 보고한다. 순간이동 금지(2번 3항)와 함께 고친다. GK가 공을 줍는 장면이 늘어 점유와 골킥 수가 바뀔 수 있으니 C.21 대비 변화를 보고한다.

## 4. 단계적 공개와 첫 플레이 안내 (D.17 4번 결과, 사용자: 추천대로) → 21.3·21.4 개정으로 넣는다 — **기획서 합침 완료(21.3·21.4, D.17 4번)**
**21.3 정보 점진 공개 (개정안)**
- 기능은 시즌 단위가 아니라 **진행 단위**로 열린다. 구현되지 않은 기능은 지금처럼 아예 숨긴다.

  | 열리는 시점 | 열리는 것 |
  |---|---|
  | 시작 | 홈, 경기, 내 선수(능력치), 리그 순위표, 세이브 |
  | 첫 경기 뒤 | 포인트 찍기(성장) |
  | 3경기 뒤 | 전술(E.19) |
  | 10경기 뒤 | 역할 선택과 덱/카드(3단계) |
  | 첫 시즌이 끝난 뒤 | 스태프, 재정(5단계) |
- 열릴 때 한 번만 짧은 소개(한두 줄 + 확인 버튼)를 띄운다. 이미 조건을 넘긴 세이브는 불러올 때 바로 열리고 소개는 한 번 보여 준다.
- **전술 화면 첫 형태**: 기본은 **성향 6종 고르기만** 보인다. 포메이션, 내 위치, 슬롯 역할, 세부 전술은 "자세히" 안에 접어 둔다(성향을 고르면 기본값이 자동으로 채워진다, E.19). 펼침 상태는 세이브에 기억한다.

**21.4 첫 시즌 가이드와 용어집 (개정안)**
- 강제 튜토리얼은 없다. 체크리스트 5개는 공개 순서에 맞춘다: 경기 하기 → 포인트 찍기 → 전술 확인 → 역할 고르기·덱 확인 → 인박스 열기(아직 구현되지 않은 항목은 숨긴다).
- **화면 첫 방문 말풍선**: 각 화면을 처음 열 때 한 줄 말풍선을 한 번 띄운다(탭하면 닫힘, "안내 끄기" 가능). 설정에 "안내 다시 보기"를 둔다.
- **첫 경기 오버레이**: 첫 경기 하이라이트의 첫 장면 시작에서 재생을 멈추고 3줄 설명을 띄운다(① 마커 색 = 우리/상대 ② 내 선수 강조 표시 ③ 이벤트 피드 위치). 탭하면 닫히고 재생이 이어진다. 한 번만 나온다.
- "?" 버튼 툴팁과 용어집은 그대로 둔다.
- 공개·안내 상태(열린 기능, 본 소개, 본 말풍선, 첫 경기 오버레이)는 세이브에 저장한다(`SAVE_FORMAT_VERSION` 올림).
- **구현 시점**: 공개 틀(조건표, 소개, 말풍선, 첫 경기 오버레이, 체크리스트 순서)은 **12단계(E3.6)**에 전술 공개와 함께 넣는다. 이후 단계는 자기 기능의 공개 조건만 붙인다.

## 5. 12단계 = 엔진 다듬기 1차를 Fable 5.1로 시험 (2026-10-15, 사용자: "이번 패치 끝나면 그대로 해 보자") → 17번 로드맵, D.14 순서 개정 — **기획서 합침 완료(17.2, D.18 3, D.14 1번)**

- **(개정, 사용자 지시) 12단계는 먼저 진단만 한다**: 코드 수정 없이 아래 1·2번의 원인과 해결 설계안을 `docs/engine-diagnosis-12.md`로 보고한다. 사용자가 보고서를 보고 구현(C.23)을 같은 세션에 맡길지 정한다.
- **12단계 범위**

- **문제 생길 부분과 처리 추천**

  7. 피부 이름(`yellow` 등)은 내부 키로만 쓰고 화면에 노출하지 않는다.
