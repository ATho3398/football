## 할 일
1. **측정 먼저**: 실제 사용 흐름(홈 → [다음]/자동 진행 → 경기 자동 → 결과 화면)에서 사용자가 기다리는 시간을 Playwright로 잰다 — PC 기본과 **폰 흉내(CPU 4배 느리게, CDP `Emulation.setCPUThrottlingRate`)** 둘 다. 구간을 쪼개 잰다: 엔진 계산(워커 안/밖) · 냉시작(워커·모듈 로드·JIT) · 다른 경기·리그 처리 · 세이브 쓰기(IndexedDB) · 결과 화면 그리기 · 연출(골 스플래시·하이라이트 생성 등) · 미리 계산이 실제로 맞아떨어지는 비율.
2. **고치기(경기 결과는 한 비트도 안 바뀌게 — 같은 시드 지문 동일)**:
   - 미리 계산을 더 일찍·확실히(경기 전날·홈 진입 때 워커에서 내 경기를 미리 돌려 두고 [다음] 누르면 바로 결과). 사용자가 경기 전에 바꾸는 것(선발·전술·카드)이 바뀌면 다시 계산.
   - 워커 미리 띄우기(앱 켤 때 데우기)로 냉시작 제거.
   - 엔진 핫패스 최적화(프로파일로 상위 함수부터 — 할당 줄이기·불필요한 재계산 캐시) — 결과 불변.
   - 결과 화면에 필요 없는 무거운 계산(하이라이트 클립·통계)을 나중으로 미루기.
   - 세이브 쓰기를 화면 전환 뒤로.
3. 목표: 자동 경기 [다음] → 결과 화면까지 **PC 0.5 s 이하 · 폰 흉내 1.5 s 이하**(미리 계산이 맞으면 거의 즉시). 직접 경기·결정 순간 흐름도 느려지지 않게.
