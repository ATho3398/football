## 1. WING 평점 6.85 (확대 경량 가드, 300경기 칸당 20명)

### 재현과 원인
`rating-parts` 600경기의 선수별 평점으로 `suite.ts analyze()`의 계산(홈 선발 45분 이상, 강도 × 포지션군 칸, **칸을 가장 작은 칸 크기로 절단**, 즉 각 칸의 앞쪽 N명만)을 그대로 돌리면:

| 표본 | 절단 | WING | 비고 |
|---|---|---|---|
| 300경기 | 칸당 20 | **6.85** | 경량 가드 값 그대로 재현 |
| 300경기 | 칸당 40 | 6.69 | |
| 600경기 | 칸당 40 | 6.69 | |
| 600경기 | 절단 없음 | **6.60** | 윙어 720명 |
| 600경기 | 절단 없음, 강도별 평균의 평균 | 6.60 | 제안 식 |

절단 표본이 커질수록 6.60으로 수렴한다. 윙어 평점은 **포지션 종류와 포메이션에 따라 크게 다르다**: LW 6.76 · RW 6.67 · LM 6.44 · RM 6.31, 포메이션 인덱스 0/1/2 = 6.38 / 6.92 / 6.51, 팀 강도 68/75/82 = 6.21 / 6.57 / 7.02. `nCell`은 가장 작은 칸(CAM·CDM이 있는 포메이션이 5종 중 1~2종)으로 정해지므로 300경기에서도 20명이고, 그 20명은 경기 순서상 앞쪽(특정 포메이션 쪽으로 치우침)이다. 포지션 평균의 표본 오차 자체도 0.8/√60 = ±0.10이라 가드 ±0.2가 2σ에 불과하다.

같은 600경기를 "칸마다 전원 평균 → 강도 3칸 평균"으로 내면 GK 6.50 · CB 6.54 · FB 6.52 · CDM 6.56 · CM 6.53 · CAM 6.53 · WING 6.60 · ST 6.68, 전체 6.56 — 모두 가드 안. 120경기만으로도 GK 6.47 · CB 6.57 · FB 6.52 · CDM 6.63 · CM 6.54 · CAM 6.73(24명) · WING 6.64 · ST 6.66.

### 처방
- **통과 기준**: 경량 포지션 평점 가드 6.3~6.7 유지. 표본은 포지션당 ≥150명(오차 ≤ ±0.07, CAM·CDM은 ≥60).
- **가설 1 (확정, 측정)**: `scripts/engine/suite.ts:467~474` — `nCell` 절단(`slice(0, nCell)`)을 없애고, 포지션 평균 = 강도 3칸 각각의 전원 평균의 평균. 전체 평균·σ도 같은 가중(칸 평균의 평균, σ는 전원). `SIZES.light.rating`은 300 그대로(CAM 60명). 예상: WING 6.61, 나머지 6.49~6.62, 전체 6.55.
- **가설 2 (기록만, C.29 이후)**: WING center 1.34는 LW/RW(라인 3, 슛 선호)와 LM/RM(라인 2)의 혼합값이라 두 집단이 ±0.2 갈린다(LW 6.76 대 RM 6.31). 포지션군을 'WING'(LW/RW)과 'WM'(LM/RM)으로 나눠 center를 따로 재면 σ 목표(0.7~0.9)에도 유리하다. 이번 패치 범위 아님.
- **재현**: `npx vite-node scripts/diag/rating-parts.ts -- 600 parts.json` 뒤 위 식으로 집계(엔진 관리자 임시 스크립트와 같다), `npm run balance:engine:check`.

## 2. 시즌 XP 비 1.19 (실제 선수 12시즌, 11명)

### 재현 (같은 12시즌 시드, `SWEEP_SEASONS=12` 나머지 0)

| | `main` C.27 (엔진 10) | 이 브랜치 C.28 (엔진 11) |
|---|---|---|
| 시즌 XP 비 (출전당, 11명) | **1.15** (가드 경계) | **1.19** |
| 실제 선수 시즌 평점 평균 (목표 6.8~7.0) | 7.71 ✗ | 7.80 ✗ |
| 케인 (시드 1) 엔진 / 빠른 | 7.59 · 18골 18도움 / 7.24 · 27골 3도움 | 8.20 · 31골 21도움 / 같음 |

| 스털링 (시드 2) | 8.27 · 24골 17도움 / 7.28 | 7.96 · 13골 16도움 / 7.28 |

- XP = max(0, 평점 − `ratingBase`) × `perRatingPoint` + 출전 + 결과(+MOM) (`src/match.ts:55 matchXp`). 그래서 XP 비는 **내 선수(실제 스타)의 엔진 평점 − 빠른 경기 평점**을 그대로 반영한다. 엔진은 케인·에릭센·스털링에게 시즌 25~34골 + 15~21도움과 평점 8.2~8.8을 주고, 빠른 경기는 7.2~7.6을 준다.
- 이 차이는 **C.26(평점 재보정: scale 0.7 → 0.9, 골 0.8·도움 0.5 등)부터**다: C.26 전체 점검(main 87da812) XP 비 1.11, 실제 선수 시즌 평점 7.69 ✗. C.27 1.15. C.28은 +0.04(케인 18 → 31골, 에릭센 25 → 34골 — GK가 루즈볼을 잡아 빌드업이 늘고, 실제 스타가 있는 팀이 그 공격을 더 많이 마무리한다. 득점 1.35 → 1.26인 동레이팅과 반대 방향이라 **강팀·스타 쏠림**의 한 증상이다).
- 즉 C.28의 문제가 아니라 "내 선수가 실제 스타일 때 엔진이 빠른 경기보다 훨씬 후하다"는 C.26 이후의 상태가 가드 경계(1.15)에 있다가 넘어간 것이다. CM 에릭센 34골은 C.29(슛 선택 규칙)가 다룰 쏠림 그 자체다.

### 처방
- **통과 기준**: 출전당 XP 비 0.85~1.15 유지(E.20 6번). 실제 선수 시즌 평점은 참고 항목이므로 그대로.
- **가설 1 (추천, 작은 수정)**: 엔진 평점의 **위쪽 압축** — `src/engine/rating.ts:88` `rating = mean + scale × (delta − center)`에서 `delta − center`가 +1.5(평점 7.85)를 넘는 부분을 절반 기울기로(모든 선수 공용, E.15.1 ①). 효과: 스타 평점 8.2~8.8 → 7.9~8.2, XP 비 1.19 → 약 1.08~1.12, 동레이팅 평점 평균·σ는 거의 그대로(상위 5%만 영향), 포지션 center 재측정 불필요. 지킬 가드: 평점 평균 6.5±0.2, σ 0.7~0.9, ST 무득점 ≥5.9, 전체 OVR +5 반응(+0.15 이상 — 상위 압축으로 조금 줄 수 있어 확인).
- **가설 2 (대안)**: 가드를 "엔진 평점 − 빠른 경기 평점 ≤ +0.3"처럼 평점으로 바꾸지 말고, 빠른 경기 쪽 스타 평점(`positionCenter`·`BALANCE.rating`)을 올려 맞추는 것은 밸런스 수치 변경이라 `BALANCE_VERSION`과 빠른 경기 XP 가드(`npm run balance`)를 같이 움직인다. 추천하지 않음.
- **가설 3 (근본, C.29)**: 스타가 있는 팀의 슛·골 쏠림(에릭센 34골)은 슛 선택 규칙(`onball.ts isMistake`, `mistakeShotGap`)으로 줄어든다. C.29 뒤 XP 비를 다시 재고, 그래도 1.15를 넘으면 가설 1.

## 3. ST 슈팅·결정력·침착성 +10 → 득점 −1.5% (120쌍)

### 표본 오차
짝지은 120쌍: 경기당 득점 차의 표준편차 약 1.0 → 평균 차의 표준오차 1/√120 = 0.09골 = **±17%**(ST 득점 0.53 기준). 측정 0 +14.5, 조정 1 +19.3, 조정 2 −1.5는 모두 이 폭 안이다(기록의 단측 95% 하한 −16.9가 그 증거). 400쌍이면 ±9%. 가드 "+5% 이상(점 추정)"은 표본 400쌍에서도 1σ 수준이라 참 효과 +12%(C.21 전체 점검 +11.5)를 두고도 20% 확률로 걸린다.

### 400쌍 재측정 (이 브랜치, `SWEEP_RESP=400`)
`SWEEP_N=40 SWEEP_RESP=400`(1,600경기, 5분): ST 경기당 득점 0.53 → 0.56, **+5.87%**(단측 95% 하한 −3.2), 유효 슈팅률 +3.06%p(하한 +1.73 ✓). 경량 가드(점 추정 +5% 이상)는 통과, E.15.1 정식 기준(방향 확실 + 70%)은 미달. C.21 전체 점검 +11.5%(하한 +2.8), C.27 경량 +27.9, C.28 측정 0 +14.5 — 400쌍 표준오차 ±9%라 "GK 패치로 반응이 줄었다"고도, "안 줄었다"고도 말할 수 없다. 120쌍의 −1.5는 표본 오차로 본다.

### 처방
- **통과 기준**: 400쌍에서 방향 확실(단측 95% 하한 > 0) + 크기 ≥ 기준의 70%(+4.8%, D.12). 경량 120쌍은 가드가 아니라 기록으로.
- **가설 1 (측정)**: `scripts/engine/suite.ts SIZES.light.response` 120 → 400(경량 점검 +2분) 또는 경량에서는 반응 가드를 떼고 전체 점검에서만 판정. 추천: 경량 400쌍, `st_shoot`만(`light: true`인 세 항목 중 득점 반응만 분산이 크다).
- **가설 2 (엔진, 400쌍에서도 음수일 때만)**: 조정 2의 `ready`(`offball.ts keeperChase()` — 우리 팀 패스가 빗나간 공이면 GK 반응 0)를 빼고 재측정. 득점 경로상 ST 슛과 무관해 보이지만 기록의 측정 순서가 이 변경 뒤에 뒤집혔으므로 확인 대상.
- **재현**: `SWEEP_N=40 SWEEP_RESP=400 SWEEP_D=0 SWEEP_D15=0 SWEEP_LEAGUE=0 SWEEP_SEASONS=0 npm run balance:quick`(약 5분).

## 4. C.31(패스 거리 곡선)에 넣을 처방: 빗나간 패스의 착지 속도

- **현상**: 상대 코너 실패 11개 중 2개가 착지 속도 33.9 · 40.3 m/s(`passSpeedMax` 26). 전체 루즈볼의 평균 착지 속도는 11 m/s지만 긴 빗나간 패스는 상한을 넘는다.
- **원인**: `src/engine/onball.ts:697~700 makePass()` 루즈 분기가 착지점을 `randn × looseError(6 m)`만큼 옮기고 **`fl.dur`을 원래 거리 기준 그대로** 둔다 → 비행 속도 = 새 거리 / 원래 시간. `src/engine/physics.ts:89 landingVelocity()`가 `d / dur`를 착지 속도로 쓰고(땅볼 `max(4, v0 − 1.2 × dur)`), `sim.ts:343`의 `keeperHands` 속도 인자도 같은 값이라 손 처리 상한 30 m/s에 걸린다. 가로채기 분기는 거리와 시간을 같이 줄여 문제없다. `cross()`는 좌표를 옮긴 뒤 `d`로 `dur`을 재서 올바르다.
- **통과 기준**: 루즈 비행 착지 속도 ≤ `passSpeedMax`(26 m/s) 100%(`polish-a`에 "착지 속도 > 26" 카운트 추가, 0회). 지킬 가드: 득점 ±0.05, 패스 성공률·롱패스 비율 불변(판정은 찰 때 끝남), 순간이동 0.
- **가설 1 (확정, 한 줄)**: `makePass()` 루즈 분기 끝에 `fl.dur = Math.max(0.2, dist(a.x, a.y, fl.toX, fl.toY) / speed)` (같은 함수 위의 `speed` 재사용). 효과: 빗나간 패스가 찬 속도로 날아가 도착이 0.1~0.5초 늦고, 착지 뒤 굴림이 짧아져 박스 안 루즈볼을 GK·수비수가 더 많이 잡는다(상대 코너 ↓, 우리 골킥 ↓). 침투 패스(`dur = max(dur, 달리는 시간)`)는 그 줄 뒤에서 다시 늘리므로 순서를 지킨다.
- **가설 2 (선택)**: `landingVelocity()`의 땅볼 하한 `max(4, …)`을 `max(2, …)`로 — 느린 빗나간 패스가 4 m/s로 "다시 가속"되는 작은 부자연. 효과 작음, 측정 뒤 결정.
- **재현**: `npx vite-node scripts/diag/polish-a.ts -- 60 78 76`(착지 속도 카운트 추가 후), `SWEEP_N=600 … npm run balance:quick`.
