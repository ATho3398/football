# 자동 진행 규칙 (사용자 확정 2026-10-16, 기획 세션 G)

기획 세션, 코드 세션, fix 세션, 엔진 관리자 세션이 모두 따른다. 코드 세션 첫 지시에는 "`docs/automation.md`를 따른다"를 넣는다.

## 0. 공통
- **모든 답변 맨 끝에 시간 기록**(사용자 지시): `명령 시각 / 답변 시각 / 걸린 시간`. 시각은 KST(`TZ=Asia/Seoul date`). 명령 시각은 그 턴을 시작하자마자 잰 시각(메시지 도착 기준, 몇 초 차이 가능), 답변 시각은 답을 쓰기 직전에 잰다. 세션 간 메시지(send_message)와 부록 C 보고에도 같은 줄을 붙인다.
- 코드·fix 세션은 Opus 5.5 고속 모드(`.claude/settings.json` `fastMode`), Fable 세션은 일반.
- 사용자 결정이 필요한 질문은 3~4개씩 추천안과 함께 묻고, 답이 없으면 추천안으로 진행한 뒤 보고한다.

## 1. 단계 흐름
1. **단계 시작(기획 세션)**: 지시를 쓰고 코드 세션 "N단계_작업명"을 연다. 직전 단계 코드 세션(그리고 그 fix 세션) 제목 앞에 `draft_`.
2. **코딩(코드 세션)**: 구현 → 검증 → 배포 → 부록 C. 엔진을 만지다 "해결 어려움"(2번)이면 더 고치지 않고 `docs/engine-issues.md`에 기록한다.
3. **문제 없음**: 기획 세션에 완료 보고 → 기획 세션이 결과를 사용자에게 보고하고 다음 단계를 연다.
4. **엔진 문제 있음**:
   - 가드를 통과한 부분까지만 main 배포, 가드가 깨지면 배포하지 않고 작업 브랜치에 둔다.
   - 코드 세션 → **엔진 관리자**(`session_01ULNad1tAcSQzVKsFKN355d`, Fable, 코드 수정 금지, 2026-10-16 교체 — 인수인계 `docs/engine-manager-handoff.md`)에 send_message(기록 경로, 브랜치, 재현 명령). 기획 세션에는 짧게 알림만. send_message가 없으면 기획 세션이 대신 넘긴다.
   - 엔진 관리자: 원인 분석 → `docs/engine-diagnosis-<패치>.md`(3번의 처방 양식) → 기획 세션에 send_message.
   - 기획 세션: 모델 선택 후 **"N단계_fix_이름"** 세션을 연다. Opus 고속 = 처방이 파일·함수·상수 단위로 좁고 명확할 때. Fable = 여러 모듈이 얽힌 구조 문제이거나 같은 문제로 Opus가 이미 2번 이상 실패했을 때.
   - fix는 문제당 1회. 실패하면 미해결 목록(`docs/engine-issues.md` 맨 위)에 올리고 다음 단계로 간다. 미해결 문제는 다음 엔진 패치 시작 때 엔진 관리자가 같이 본다. 단, 다음 단계가 그 문제 위에서만 가능한 작업이면 멈추고 사용자에게 묻는다.
5. **기획 세션 교체**: (세션 깊이 제한 8: 기획 세션이 다음 기획 세션을 만들면 한 세대씩 깊어진다. 깊이는 `get_session`의 `lineage`로 확인, 7 이상이면 사용자에게 앱에서 직접 열어 달라고 요청) 단계를 연 직후 자기 `get_session`으로 확인해 컨텍스트 50만 토큰 또는 비용 15달러 중 먼저 닿으면(2026-10-17 12:00 사용자 확정, 25만 → 50만) → 인수인계 갱신 → 새 기획 세션 생성 → 지금 세션 `draft_` → 실행 중인 코드 세션·엔진 관리자에게 새 기획 세션 ID를 알린다.

## 2. "해결 어려움" 기준 (코드 세션)
하나라도 해당하면: ① 같은 목표 조정 3회 연속 실패(패치당 조정 2회를 다 쓰고 미달 포함) ② 한 지표를 맞추면 다른 가드가 깨지는 일이 2회 이상 반복 ③ 원인을 못 찾은 이상 동작(재생 이상, 결정성 깨짐) ④ 표본 2배에도 판정이 바뀜 ⑤ 경기 계산 2초 초과 ⑥ E.15.1 원칙(결과 할당·고무줄 보정)을 어기지 않고는 불가능.

## 3. fix 세션 규칙
- **처방 양식(엔진 관리자가 반드시 적는다)**: 통과 기준(목표 지표·범위, 지킬 가드), 우선순위 가설 최대 3개(가설마다 손댈 파일·함수·상수), 재현 명령과 현재 측정값.
- **예산**: 2시간(CI 대기 제외, 1시간에 중간 점검), 측정 최대 6회(가설 3 × 조정 2), 빠른 표본으로 판단하고 전체 시즌 점검은 마지막 1회. 비용 상한 Opus 10달러 / Fable 20달러(자기 `get_session`의 비용).
- **실패 판정(하나라도 해당하면 즉시 중단)**: ① 2시간 초과 또는 비용 상한 초과 ② 가설 3개 소진 ③ 연속 2회 시도에서 남은 차이가 25% 이상 줄지 않거나 나빠짐 ④ 목표를 맞추면 다른 가드가 깨지고 1회 더 고쳐도 둘 다 통과 못 함 ⑤ 진단 불일치: 시작 20분 안 측정에서 처방이 가정한 원인이 재현되지 않음 ⑥ 범위 밖(세이브 구조·화면·다른 시스템 수정 필요, E.15.1 위반).
- **결과 처리**: 성공(기준·가드 통과) → 배포, 보고, 다음 단계. 부분 해결(남은 차이 50% 이상 감소 + 가드 통과) → 배포, 나머지는 미해결 목록. 실패 → 배포하지 않고 브랜치에 기록(시도와 측정값) → 기획 세션 보고 → 다음 단계.
- **진단 불일치(⑤)**: 그 문제에 한해 엔진 관리자에게 1회 되돌려 재진단 → 재진단 뒤 fix도 실패하면 미해결로 넘긴다.
