# 기획 세션 인수인계 (기획 세션 → 다음 기획 세션)

이 문서는 기획 세션을 새로 열 때 읽는 안내서다. 기획 내용 자체는 `docs/game-design.md`가 전부이고, 여기에는 작업 방식과 현재 상태만 적는다.

## 1. 역할과 규칙
- 이 세션은 **기획 전용**이다. 코드는 건드리지 않고 `docs/` 문서만 수정한다. 모든 답변은 **한국어**로 한다.
- 사용자와 진행하는 방식: **질문을 3~4개씩 묶어서** 하고, 각 질문마다 **추천안 1개와 이유 한두 줄**만 말한다. 사용자가 "추천대로"라고 하면 그대로 확정한다. 확정되면 `docs/game-design.md`에 반영한다.
- **사용자의 요구는 요약해서 되돌려 확인한다.** 예전에 사용자가 "22명이 전부 본인 스탯에 맞춰 엔진으로 움직여야 한다"고 말했는데 이를 "팀별 사이클 추상화"로 잘못 설계했다가 되돌린 일이 있다. 구현 비용이 큰 결정은 원문 그대로 인용해서 확인한다.
- **코드 세션이 돌고 있을 때는 기획서를 수정하지 않고 보고만 한다.** 확인 방법: `list_sessions`(mine: true)로 상태가 RUNNING인지 보고, `git fetch` 후 `origin/main` 로그를 본다. 쉬고 있으면(IDLE/COMPLETED) 수정해도 된다.
- 문서만 바뀌는 푸시는 `main`에도 올려도 된다(사용자 허가). **코드가 바뀌는 푸시는 사용자에게 먼저 묻는다.** 브랜치는 `claude/confident-meitner-3gjy8r`(기획 브랜치)와 `main`을 같은 커밋으로 맞춘다. PR은 사용자가 요청할 때만 만든다.
- 커밋 메시지 끝에 `Co-Authored-By`와 `Claude-Session` 줄을 붙인다(시스템 안내를 따른다).

## 2. 사용자 선호
- 현실감을 중시한다(2018년 기준 실제 데이터, 금액도 실제와 비슷한 규모, 단 천문학적 금액은 제외).
- 캐주얼한 성장(훈련 선택이 아니라 경기 활약으로 XP를 얻고 포인트를 찍는 방식), 목표 깊이는 FM의 60~70%.
- **게임 실행 중 AI API 호출은 없다.** 전부 순수 코드(오프라인, 서버 없음).
- 비용과 세션 횟수에 상한은 없다. 다만 효율을 우선한다(세션당 한 덩어리, 필요한 섹션만 읽기).
- 코드를 직접 보지 않는다. 결과는 부록 C 소절과 `main` 로그로 확인하고, 이해하기 쉽게 설명해야 한다.

## 3. 현재 상태 (2026-10-14)
- 완료: 1단계, 1.5, 1.6, 1.7단계(`main`에 배포). 폼(D.1)과 부상(D.2)도 구현됨.
- 다음: **R단계(팀 로스터 생성기, 23번) → 2단계 경기 엔진 E1~E5(부록 E, 22명 에이전트 시뮬) → 3단계 카드(부록 F) → 4단계 잔여 → P단계 → U단계 → 5단계**. 자세한 순서는 `game-design.md` 17번.
- 무인 코딩 범위: R단계와 E1~E3까지. **E4(내 선수 개입), E5(경기 화면), 5단계는 사람이 확인한 뒤에 시작**(부록 H.1).
- 코드 세션은 `main`으로 푸시한다. 기획 세션은 기획 브랜치와 `main`을 맞춘다.
- UI: 사용자가 **Claude Design**으로 디자인 중이다(요청서 `docs/ui-spec-for-design.md`, 화면 명세 부록 I). 산출물은 `docs/design/`에 보관할 예정이다.

## 4. 열린 항목 (새 세션이 이어서 할 일)
1. **디자인 결과가 도착하면** 화면 관련 섹션(21, 부록 E의 화면 부분, F.6, 부록 I)을 개정하고 U단계 적용 명세를 쓴다.
2. 코드 세션이 부록 C에 새 소절을 남기면 읽고, "기획 세션에서 정할 것" 질문에 추천안으로 답한다. 엔진 통계 목표(E.15) 미달 항목이 생기면 조정안을 낸다.
3. E3 결과를 사용자가 확인한 뒤 E4 시작 지시를 준비한다.
4. 5단계 착수 전 상세 보강: 화면 구조, 세이브 구조, 수치 점검.
5. 확정: 엔진에 **오프사이드 포함**(사용자 결정). 파울과 카드도 포함.
6. 문서가 길다(약 1,300줄). 코드 세션 읽기 비용을 줄이려면 상단 "단계별 필독 가이드"를 갱신하고, 오래된 부록(B, C)은 역사 기록임을 유지한다.

## 5. 새 세션이 가장 먼저 읽을 것
1. 이 문서 → 2. `docs/game-design.md` 상단 "단계별 필독 가이드", 17번 로드맵과 17.1 진행 현황, 부록 H → 3. 부록 C의 가장 최신 소절(코드 세션 보고) → 4. 사용자가 지금 하려는 작업의 섹션.
