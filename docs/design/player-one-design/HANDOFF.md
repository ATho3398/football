# PLAYER ONE — 디자인 핸드오프

싱글 플레이 축구 커리어 웹 게임 **PLAYER ONE**의 UI 디자인 묶음이에요. 이 문서를 먼저 읽고 구현을 시작하세요.

- 기준 화면: 모바일 세로 **390×844**, 한국어 UI, 다크 테마 우선(라이트 토큰도 있음).
- 스타일 이름: **볼트(Volt)** — 어두운 그래파이트 바탕 + 평평한 볼트 라임(#d6ff3c) 면. 발광·그라데이션 장식, 스크린톤(망점), 글자 그림자는 쓰지 않아요.
- 화면의 문구·수치는 기획서 규칙에 맞춰 두었어요. 기획서와 다르면 **기획서가 우선**이에요.

## 폴더 구조

```
player-one-design/
├─ HANDOFF.md                  ← 지금 이 문서
├─ index.json                  ← 화면 번호·그룹·이름·크기·파일 경로 목록
├─ design-system/
│  ├─ README.md                ← 브랜드 규칙(색·글꼴·카드·전술·화면 골격). 반드시 읽기
│  ├─ tokens.json / tokens.css ← 디자인 토큰(다크/라이트) · CSS 변수 + @font-face
│  ├─ fonts/                   ← Pretendard Variable, Poppins 500~800
│  └─ components/
│     ├─ bundle.js / bundle.css ← 컴포넌트 기준 구현(React 18, window.PlayerOne.*, po- 클래스)
│     ├─ index.d.ts            ← 모든 컴포넌트 props 타입
│     └─ <컴포넌트>/README.md   ← 컴포넌트별 규칙 (+ preview.html)
└─ screens/
   ├─ index.html               ← 전체 화면 갤러리(브라우저로 열기)
   ├─ png/                     ← 화면 캡처 159장 = 시각 기준
   ├─ html/                    ← 화면별 실행 가능한 HTML(실제 컴포넌트로 렌더)
   ├─ source/                  ← 캔버스 원본(.dc.html)
   └─ lib/                     ← html 화면용 React·번들·토큰·폰트·작은 런타임
```

## 화면 보는 법

- 가장 빠른 길: `screens/png/` 이미지.
- 실제 렌더: `screens/index.html`을 브라우저로 열기. 안 열리면 `screens/`에서 `python3 -m http.server`.
- 각 html은 `<template id="tpl">`(마크업)과 `<script id="code">`(그 화면의 샘플 데이터 `renderVals()`)로 되어 있어요. `<x-import component-from-global-scope="PlayerOne.X" kebab-props="{{값}}">` = 컴포넌트 X에 props 전달, `<sc-for>` = 반복, `<sc-if>` = 조건부. 화면마다 어떤 컴포넌트에 어떤 데이터가 들어가는지 여기서 읽을 수 있어요.

## 구현 가이드 (클로드 코드에게)

1. **토큰부터.** `tokens.json`/`tokens.css`를 프로젝트 테마로. 색은 토큰 변수로만. 테마는 `<html data-theme="dark|light">`.
2. **컴포넌트는 `bundle.js`가 기준 구현.** TSX로 옮길 때 `index.d.ts` props와 `bundle.css` 클래스·치수를 지키세요.
3. **화면은 `screens/png`에 맞추고**, 구조·데이터는 `screens/html`의 template·code를 따르세요. 샘플 데이터는 실제 게임 데이터로 교체.
4. 컴포넌트 README의 문구 형식·상태 표현 규칙을 지키세요. 아이콘은 `Icon` 내장 SVG만 사용.

## 꼭 지킬 규칙 요약

- 라임(`brand`)은 면으로, 한 화면에 한 번 크게(`HeroPanel`). 숫자는 문장으로 설명. 확률 변화는 ▲초록 / ▼빨강 + 출처("+8 카드").
- 숫자 글꼴 Poppins, 한국어 Pretendard, 해요체.
- **카드 종류 7종:** 플레이 · 세트피스 · 패시브 · 콤보 · 관리 · 시그니처 · 지시(5단계에서 활성).
  - **포지션군 태그**(공용/공격/미드/수비, `pos`)는 종류와 별개. 수비 플레이 카드 = `type: 'play'` + `pos: 'def'`.
  - **지시**는 `order: 'follow'`(이행 = 내가 정한 역할대로 팀플레이 → 팀 결과·감독 신뢰도 +) / `'solo'`(독단 = 역할을 벗어난 개인 플레이 → 성공 시 평점 +0.8, XP ×1.3 / 실패 시 감독 신뢰도 −5). 기준은 사용자가 전술 화면에서 정한 슬롯 역할.
  - **시그니처**는 모두 희귀, 그 역할일 때만 사용(아래 표). 역할이 다르면 회색 + "역할 불일치" + [교체 제안].
  - 라보나 크로스 = 에픽 · 플레이 · 공격(시그니처 아님).
- 덱: 세트피스 최대 3장, 같은 카드 최대 2장. 덱 슬롯은 **위상 티어에 따라 8~14장**(일반 티어 김민준은 8장부터, 면담 보상 +1을 받아도 최대 14). 덱 화면 샘플은 8장 기준.
- 포지션 라벨은 CAM/CDM(AM/DM 쓰지 않음).
- 위상 표기: 티어 이름(일반/스페셜/탑클래스/월드클래스/레전더리) + 점수. 예: "위상 일반 · 12점".
- 결정 순간 패널: 선택지 3개(안전/균형/도박) → 패 카드 줄 → [맡기기](보조) [확정](주). 플레이 카드를 고르면 카드 희귀도 색 테두리의 4번째 선택지.

- **경기 = 하이라이트(요청서 4).** 경기당 약 90초, 장면 6~8개(각 10~15초, 1× 실제 속도, 공격이 시작되는 순간부터). 장면 사이 약 1초 전환: 선수가 다음 위치로 미끄러지고, 시계가 넘어가고, 피드에 요약 한 줄.
  - 상단 띠(`ScoreBar` `view`): 하이라이트 "하이라이트 · 장면 3/7 · 23' 역습" + [여기서부터 실시간] / 장면 전환(배속·실시간 비활성) / 실시간 "실시간 · 31'" + [하이라이트로 돌아가기] / 하프타임은 "하프타임"만. 결정 순간도 장면의 하나라 띠 유지. 재개 대기는 띠 아래 "스로인 준비" 라벨(`sceneNote`). 샘플 장면 수는 7.
  - 띠 오른쪽 끝 **톱니 = 경기 설정 시트**(정지 빈도·빨리 감기).
  - 배속 1×/2×/4×는 장면 안에서만. 건너뛰기(⏭)는 **경기 전체**: 남은 경기를 바로 계산해 결과 화면으로. 다음 장면으로 넘기는 버튼은 없음. 확인 모달 "경기 결과로 건너뛸까요?", 직접 모드면 "남은 결정 순간은 엔진이 대신 골라요. 카드는 쓰지 않아요." 한 줄 추가.
- **버전 표시:** 홈 맨 아래·경기 설정 시트·타이틀에 보조 글씨 "버전 C.18 · 엔진 6 · 밸런스 14 · 2026-10-15 배포 (커밋 82e27e0)". 세이브 시작 버전이 다르면 홈에 중립 배너, 세이브 슬롯마다 "C.16에서 시작".
- **경기 후 평균 위치:** 리포트 탭 "전술 리포트 · 평균 위치"에 양 팀 11명 평균 위치(정지 피치, 홈 팀이 오른쪽으로 공격).

## 수치 규칙 (화면에 쓴 값)

- **감독 신뢰도:** 보상 면담은 신뢰도 80 이상. 경기 후 예시 +4(평점 7.0 이상 +2, 골 +1, 승 +1). 훈련은 신뢰도에 영향 없음.
- **보상 면담 선택지:** 선호 슬롯 보장(다음 5경기) · 덱 슬롯 +1(이번 시즌, 최대 14장) · 주전 보장.
- **경기 후 XP 예시:** +25(다음 레벨까지 200 기준).
- **주전 경쟁 점수** = 슬롯 OVR + 신뢰도 보정 + 폼 보정 + 피로 보정. NPC 경쟁자의 신뢰도 보정은 +0.6(신뢰도 60 고정), 피로 보정은 피로 70 이상일 때만 −2. 예: 김민준 62.4(60 + 0.6 + 1.8) vs 오현우 64.1 → 선발 확률 24%.
- **훈련(하루):** 기술 XP +1.0 · 피로 −3.5 / 고강도 +1.5 · −2 / 포지션·역할 +0.5 · −4 / 세트피스·카드 +0.5 · −4 / 영상 분석 +0.5 · −4.5 / 회복 0 · −5.5 / 휴식 0 · −6. 묶음 게이지는 하루 +1칸(30칸), 주간 XP 상한 6.
- **휴가:** 휴가 중에는 폼이 떨어지지 않음. 리그 외 경기가 있으면 그 일정에서 멈춤.
- **이적시장:** 여름 시장은 개막 전(비시즌)까지, 겨울 시장은 1월. 9월 샘플에는 이적시장 배지 없음.
- **날짜 샘플:** 9/2 A매치 휴가(9/8까지, 9/5 리그컵에서 멈춤) → 9/9 하루 진행 → 9/12(토) 리그 5R 리버풀전 → 9/14~20 훈련 주간, 9/19 리그 6R.

## 요청서 5 반영 (2026-10-17) · 57~123번

실제 플레이 캡처(손흥민 · 토트넘 홋스퍼 · 2018-19 프리미어리그)의 값을 그대로 썼어요. 캡처가 서로 안 맞던 곳(예: 경기 결과 4-2인데 하이라이트가 3-2에서 끝남)은 맞는 쪽으로 고쳐 그렸어요.

### 핵심 문제 → 해결
1. **결정 순간 한 화면(77~79):** 압축 스코어 줄(약 80px) → 상대 진영만 자른 세로 피치(`Pitch orient="vertical" crop={[56,100]}`) → `ChoiceButton compact` 2~3개 → 카드 패 칩 한 줄(38px, 누르면 확률 바로 반영) → [맡기기][확정]. 독 위 772px 안에 다 들어가요. 4번째 선택지가 생기면 피치를 [72,100]으로 더 잘라요.
2. **이름표 겹침(74):** 내 선수(시안, 항상) → 공 가진 선수(흰, 항상) → 공에 가까운 순서로 아래·위 자리 찾기 → 겹치면 짧은 이름 → 그래도 겹치면 숨기고 번호 원만. `Pitch`에 구현돼 있어요(`collide={false}`로 끔).
3. **글자 머리말(100):** 숫자가 아니면 48px 한 줄 6자 이내("계약 만료"), 자세한 건 eyebrow·칩으로. `HeroPanel`이 자동 판별.
4. **긴 화면:** 선수 3,994 → 탭 4개(93~96, 각 900~1,200) · 설정 3,335 → 1,009(섹션 접기 + 이동 칩, 선수 이름·페이스온은 별도 화면) · 홈 2,840 → 약 1,000 · 새 게임 2,761 → 1,865 · 경기 결과 2,595 → 2,087(결정 기록 3줄 + 더 보기, 전술 지표 3줄).
5. **반복 머리말:** 덱·설정·월드·선수·시즌 상세는 `HeroPanel compact`(약 130px).
6. **6탭(107~112):** `Tabs segment cols={3}` 3×2 바둑판. PC는 한 줄.
7. **빽빽한 곳:** 주간 7칸 = `DayCell`(요일·날짜·아이콘·2글자, 값은 시트에서). 포인트 찍기(113)는 compact 머리말 + OVR 한 줄 + 비용 칩 → 첫 화면에 능력치 2줄 이상, 고른 박스에 [−][+]와 비용·OVR 변화가 같이 남아요.

### 새 컴포넌트 (design-system/components 에 README · preview · props 타입)
`Dock`(폰 6 / PC 9, 진행 칸 5상태 · 배지 · 잠김) · `AttrTile`/`AttrGrid`(1~20, 색 구간 17+ 라임 / 15+ 초록 / 13+ 하늘 / 10+ 흰 / ~9 주황, 편집 상태) · `DayCell` · `OfferCard`(임대 표시) · `TransferRow`(빈자리 보충 줄) · `TextField`.
기존 확장: `Pitch` 세로·마커(등번호/얼굴/도트 16px 정수배)·크기·이름 표시 · `HeroPanel compact`·글자 머리말 · `Tabs scroll`·`cols` · 아이콘 12종(menu, deck, chat, trophy, swap, edit, eye, grid, face, sliders, pin, collapse).

### 설계 판단 (확인 부탁)
- 독 진행 칸: 응답이 필요한 일이 있으면 "답하기"(주황 + 남은 수). 비시즌 홈(88)·이적 제안(97~100)에 적용했어요. 자동 진행 중(62~63)은 "경기 중" 상태를 같이 써요.
- 이적 제안(97): 5개 중 하나(리버풀)를 임대 1년으로 바꿨어요(요청: 임대 1 섞임). 주급이 모두 같아서 목록 위 한 줄로 빼고, 선택한 제안만 `OfferCard`로 펼쳐요.
- 겨울 제안(99)의 바이에른 뮌헨·AS 로마 제안, 이적료·주급 수치는 디자인용 예시예요.
- 능력치 묶음 이름은 요청서대로 몸 다루기 · 마무리 · 패스·시야 · 수비 · 스피드 · 피지컬 · 정신. 민첩성은 몸 다루기로 옮겼어요.
- 기술 훈련 게이지는 요청대로 4묶음(볼·마무리·패스·수비)만 보여 주고, 나머지 3묶음은 [자동]일 때 함께 돈다고 안내해요.
- 캐릭터 마커 도트: 보통 = 16px(도트 2px), 크게·아주 크게 = 32px(도트 4px). 정수배만.

## 요청서 6 반영 (2026-10-18) · 124~159번

기준 빌드 34d단계 · 버전 C.48 · 엔진 20 · 밸런스 35(커밋 66ba91f). 캡처(커스텀 선수 이도윤 · 리버풀 1군 테스트, C45~C48 확인 캡처)의 문구·수치를 썼어요. 154~159는 캡처 없이 기획 설명대로 그렸어요. **5차보다 우선하는 것**: 독(홈 가운데), 경기 끝 = 결과 화면, 통용 이름, 경기 준비, 훈련 프리셋, 다른 팀·선수 상세.

### 핵심 문제 → 해결
1. **커스텀 생성 5,785px → 6단계(124~129).** 기본 · 몸 · 외모 · 태그 · 능력치 · 시작. 위 점 6개(지난 단계 ✓, 누르면 이동) + `PointBar`(sticky) + 아래 고정 [이전][다음 · 단계명]. 한 단계 = 거의 한 화면(124 915 · 125 844 · 126 877 · 127 1,328 · 128 1,550 · 129 1,771). 접기 한 화면보다 단계를 고른 이유: 포인트가 단계마다 바뀌는 걸 띠 하나로 계속 보여 줄 수 있고, 태그·능력치처럼 긴 목록이 서로 밀어내지 않아요. 시작 방식 탭(랜덤/커스텀/실제 선수)은 1단계에만. PC(151)는 단계 목록을 왼쪽에 늘 보여 줘요.
2. **실제 선수 + 레전드 10,331px → 1,586(131).** [실제 선수 18 | 레전드 107] 묶음 탭 → 고른 선수 고정 카드 → 검색(이름·시작 구단·유스) + 정렬(전성기순) + 포지션군 → 10명 + "20명 더 보기". 줄 오른쪽 = 지금 OVR → 전성기 OVR(레전드 금색).
3. **설정 목록 4개 → "꾸미기" 하위 화면 4개.** 설정(66)에는 목록을 두지 않고 "꾸미기" 섹션 한 줄씩(선수 이름 71 · 경기 아이콘 137/138 · 페이스온 68 · 카드 이미지 140~142). 하위 화면 위에 꾸미기 이동 칩(4개)이 있어 서로 바로 가요. PC(152)는 설정 섹션이 왼쪽 목록.
4. **선수 화면 새 칸 → 탭 "몸·태그" 추가(134).** 탭 = 능력치 · **몸·태그** · 포지션 · 기록 · 계약. 몸·태그 = 신체 5칸 · 약발 +1 · 태그 대표 4 + [전체 보기](135 시트) · 유스 출신 · "내 모습"(얼굴 · 경기 아이콘 · 이름표, 프로필 줄 [얼굴] 버튼은 [꾸미기]로). 몸값·바이아웃·재정 등급은 계약 탭(136).
5. **태그 구분(`TagChip`).** 색 = 장점(초록)/단점(빨강)/효과 없음(회색 테두리). 맨 앞 기호 = 종류(± 생성 · 핀 커리어 · 별 플레이 · 말풍선 스토리). 점선 테두리 + 시계 = 해제형, 취소선 = 해제됨. 칩 안에 설명을 넣지 않아요(라임 알약에 3줄 넣던 것 해결) — 설명은 시트 줄.
6. **긴 이름 + 칩.** 이름 줄에는 이름만(한 줄 · 말줄임), 칩은 고정 자리(메타 줄 맨 앞 · 카드 위 줄 · 오른쪽 열)에 nowrap. 레전드 목록 안에서는 묶음 탭이 레전드라 칩을 생략. 이름은 통용 표기(요한 크루이프 · 호나우두 · 페테르 슈마이켈 · 에우제비우).
7. **카드 그림 섞임(144).** 그림 없는 카드 기본 장면 = 단색 + 하프라인 + 종류 아이콘(희귀도 색 55%). `GameCard` 기본값이 바뀌었어요(예전 골문 장면은 `placeholder: 'scene'`). 못 쓰는 카드는 이유 칩을 위로 옮겨 이름을 가리지 않아요.
8. **비슷한 유니폼(139).** 도트 캐릭터 아래 번호 띠(홈 라임 · 원정 주황) 항상 + 몸통 밝기 차이가 작으면 원정 몸통 주황 테두리(`Pitch kitClash`). 유니폼 코드(S01 · C05) 디버그 문구는 화면에서 빼요.
